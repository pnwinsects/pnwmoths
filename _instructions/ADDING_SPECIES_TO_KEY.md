# Task: Add Species to the Identification Key

## What This Changes

- `data/key-scores.csv` gets new rows: one per species, with a `1` in each character-state it has
- `data/key-matrix.json`, `data/key-coverage-report.json` and `data/key-template.csv` are regenerated by `npm run build:key`
- After deploy, the species appears in Identify (`/identify/`) results

Background: [ADR 0048](../docs/adr/0048-key-scores-one-row-per-species.md), issue [#390](https://github.com/pnwinsects/pnwmoths/issues/390).

## How the key is stored

`data/key-scores.csv` has **one row per species and one column per character-state**. The first column, `binomial`, holds the name, e.g. `Pheosia californica`. Each of the other 237 columns is headed with a full question and answer, such as `Forewing color and pattern:Color:Main color of forewing:Brown`.

- `1` means the species has that state.
- Blank means **not scored**. A blank never rules a species out. If you are unsure, leave it blank.
- A species can have several states of one question (e.g. two forewing colors). Identify treats answers within a question as OR, and answers across questions as AND.

## For the curator: scoring species

1. Download the template from the **Identification key template** entry on the site's `/curation/` page. It is also `data/key-template.csv` in the repository. It lists every species we hold that the key does not score yet: published species first, then the withheld Geometridae, each in checklist order.
2. Open it in Excel. Freezing the top row and the first column (View → Freeze Panes) keeps the questions and names in view.
3. For each species you score, put a `1` in every cell that applies. Don't type `x`, `Y` or `yes`; the merge rejects anything but `1`, `0` or blank, and names the cell.
4. Leave rows you don't get to as they are. Rows with no `1`s are skipped. You can also delete them.
5. Don't edit, reorder, add or delete **columns**. If the columns differ from the key's, the merge refuses the whole file.
6. Save as **CSV UTF-8 (Comma delimited)** (in Google Sheets: File → Download → CSV). Attach it to a GitHub issue (#390, or a new one), or send it to a maintainer. Whether the curator works in Excel or a shared Google Sheet is still open on #390; this step will change to match.

To **correct** a species the key already scores, say which cells to change. The merge never overwrites existing scores; a maintainer edits that row in `data/key-scores.csv` directly.

## For a maintainer: merging a filled-in template

You will need Node 24 (see `.nvmrc`) and a checkout with `npm install` done.

```bash
npm run key:merge -- path/to/filled-template.csv
npm run build:key
npm test
```

`key:merge` prints what it did:

- **appended N species**: their rows are now at the bottom of `data/key-scores.csv`.
- **skipped N row(s) with no scores**: template rows nobody filled in. Expected.
- **left N already-scored species untouched**: the file had rows for species the key already scores. If they are corrections, apply them to `data/key-scores.csv` by hand on purpose.
- **Nothing written: N name(s) match no species**: almost always a typo in the name column. Fix the name in the file and rerun. A name that is a real synonym needs a `data/species-synonyms.csv` row first; see [CURATING_SPECIES_SYNONYMS.md](CURATING_SPECIES_SYNONYMS.md).

`npm run build:key` should report one more matched species for each row appended. Commit everything it changed under `data/` in the same change. The staleness test in `scripts/build-key.test.ts` fails if `data/key-matrix.json` or `data/key-template.csv` is out of date.

Withheld species (the Geometridae) can be merged before they are published. They stay out of Identify until their family is released from `data/withheld-families.csv`.

## Editing the file directly

`data/key-scores.csv` is a plain CSV, so one or two cells can be changed in any editor, or in Excel if you save as CSV UTF-8. `npm run build:key` checks every cell and fails with the line and column of anything that is not `1`, `0` or blank. It also fails on a species named on two rows.

Don't add, remove or move columns without engineering help. A column's position is its `char_id`, and `data/key-character-images.csv` uses that position to attach each question's help image.

## Troubleshooting

- **"contains non-UTF-8 bytes"**: the file was saved as plain "CSV" rather than "CSV UTF-8". Re-save it.
- **"columns do not match"**: the template predates a change to the key's columns. Download a fresh one and copy the scored rows across.
- **"matrix.length invariant failed"**: a column was added or lost in `data/key-scores.csv`. Compare its header against `git show HEAD:data/key-scores.csv`.
