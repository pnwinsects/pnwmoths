# 0021. Share previews are built from factsheet prose and CDN photos, with one committed fallback card

**Status:** Accepted

## Context

Linking to the site from BlueSky, Slack, or a group chat produced a bare card: the page title and the
bare domain, nothing else ([#198](https://github.com/pnwinsects/pnwmoths/issues/198)). The site
emitted no `<meta name="description">`, no Open Graph tags, and no canonical link at all.

Three things had to be settled before the tags could be written.

**Where the descriptions come from.** There are ~1,265 species factsheets. Hand-authoring a
description for each is not work anyone is going to do, and a templated
"*Genus species* — a moth" sentence carries no information a reader could not get from the title.
But the factsheets already open with a one-sentence diagnosis written by a lepidopterist —
"*Abagrotis apposita* is a mottled brick-red, medium-sized moth (FW length 14–17 mm) that flies in
forests in late summer" — which is a better description than anything we would write by hand.

**What origin the URLs use.** `og:url`, `og:image`, and `rel=canonical` must be absolute.
`pathPrefix` ([ADR 0008](0008-deploy-bunny-additive.md)) supplies a path, never an origin, and the
site has two deploy targets: production on Bunny at `moths.pnwinsects.org`, and manual GitHub Pages
staging under `pnwinsects.github.io/pnwmoths/`.

**What image non-photo pages share.** Species and plate pages have photographs already on the CDN.
The home page, Browse, Identify, Glossary, FAQs, and About do not. The site's own banner,
`public/images/header.png`, is 1153×78 — a strip far outside the 1.91:1 that link previews expect,
and every consumer would either letterbox or reject it.

## Decision

**Descriptions are derived, not authored.** [`src/_lib/social-meta.ts`](../../src/_lib/social-meta.ts)
lifts the first substantive paragraph of a factsheet's Markdown, strips inline markup, and truncates
it to 200 characters at a sentence boundary (falling back to a word boundary, which is the only case
that gets an ellipsis). Species with no prose on file get a taxonomy-derived sentence that states
what the page contains rather than inventing natural history. Every other page carries a
hand-written `description:` in its front matter; a test fails the build's test suite if a page
rendered through `base.njk` has none.

**`SITE_ORIGIN` mirrors the `pathPrefix` switch.** `eleventy.config.ts` derives it from
`process.env.GITHUB_PAGES`, exactly as `pathPrefix` is derived, and an `absoluteUrl` filter composes
the two: `{{ page.url | url | absoluteUrl }}`. Staging therefore advertises staging URLs and never
claims to be production.

**Share images come from the CDN where a page has one.** Species use the lead specimen photo (the
high-res thumbnail at `?width=1200` when available, else the lead legacy image); plates use the
thumbnail the plate index grid already loads. Everything else falls back to
`public/images/social-card.png`, a committed 1200×630 card generated by
[`scripts/generate-social-card.ts`](../../scripts/generate-social-card.ts) from the existing banner
and site wordmark. Alt text tracks the *image*, not the page, so a species with no photos does not
describe the site card as a specimen photograph of itself.

## Consequences

- Descriptions improve for free as the factsheets are edited; no second copy to keep in sync.
- A malformed factsheet shows up in the share card. Fixing #198 surfaced one
  (`euxoa-lineifrons.md` had stray emphasis markers around non-breaking spaces, a legacy CMS
  artifact, which also italicised its whole opening paragraph on the page). `stripMarkdown` now
  drops unbalanced markers so a future typo degrades to plain text rather than leaking an asterisk.
- The card PNG is a committed build artifact, in the spirit of
  [ADR 0017](0017-reproducible-committed-artifacts.md): `npm run generate:social-card` is
  maintainer-run, not part of `npm run build`, so the site build stays offline and deterministic.
  It is the one image asset in the repo that is not a logo — [ADR 0007](0007-bunny-cdn-images.md)
  keeps *photographs* on the CDN, and the card is site chrome, like the banner it is made from.
- Species share images are requested from Bunny's optimizer as `?width=1200&format=jpg`.
  The `format` is not cosmetic: the stored high-res tile is WebP, which X documents support
  for, but Facebook documents only JPEG/PNG/GIF and LinkedIn and WhatsApp are both
  unreliable with — and that branch covers 1,155 of the 1,253 species pages.
- **Known limitation: plate previews are undersized.** The only plate image on the CDN is a
  240×300 thumbnail, and the optimizer does not upscale. That is below X's 300×157 floor for
  `summary_large_image`, so X will drop the image or downgrade the card; Facebook and
  LinkedIn render it small. Accepted for ~50 pages, because a real image of the plate beats
  the generic card on Bluesky, Slack, Discord and Signal, which render small images fine.
  Producing proper 1200px plate share images from the deep-zoom tiles is separate work.
- Absolute URLs are load-bearing beyond correctness: eleventy-plugin-vite's HTML scanner treats
  every `<link href>` and the `og:image` `content` as a local asset to copy, and skips only external
  URLs. A root-relative canonical would reproduce the `EISDIR` build failure documented in
  [`src/species-redirect.njk`](../../src/species-redirect.njk).

## Alternatives rejected

- **A `description:` field per species in `data/species.csv`.** Contributor-editable, consistent with
  [ADR 0002](0002-flat-files-over-cms.md) — but 1,265 empty cells that would stay empty, duplicating
  prose that already exists.
- **Rendering share cards per species** (name and photo composited at build time). Better-looking
  previews, but ~1,265 generated PNGs to store and upload for a marginal gain over the specimen
  photo itself.
- **No image on non-photo pages.** Zero new assets and zero risk, but the home page is the most
  shared URL on the site and it would have been the one page with a blank preview.
- **Pinning a representative species photo as the site default.** No new repo asset, but the choice
  is arbitrary and the URL breaks silently when that species' photos are re-ingested.
