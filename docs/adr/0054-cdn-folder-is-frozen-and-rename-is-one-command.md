# 0054. A photograph's CDN folder is frozen when it is published, and a species rename is one command

**Status:** Accepted · Refines [0038](0038-photo-identity-is-data-not-filename.md) · Issue [#417](https://github.com/pnwinsects/pnwmoths/issues/417)

## Context

A species slug does three jobs at once. It is the public address of the account page, it is the key that joins about 15 data files, and it is the name of the folder that holds the species' photographs on the CDN. The slug is derived from the scientific name, and scientific names are what the curator keeps changing.

The cost shows in [#416](https://github.com/pnwinsects/pnwmoths/pull/416), which renamed six species to MPG's spelling. Five of the six changed by one letter, for example *Malacosoma californicum* to *californica*. The pull request touched 26 data files, re-keyed 158 rows of `data/image-derivatives.csv`, and needed a 172-line script that copied 4,023 objects to new CDN folders. A maintainer had to run that script with the Bunny password before the deploy, and until it ran the photographs on five public pages returned 404. We carry 26 redirects, 76 synonym rows and about 120 commits about renames or genus fixes. `docs/lessons-learned.md` has a lesson from most of them.

[ADR 0038](0038-photo-identity-is-data-not-filename.md) already decided that a photograph's filename is a permanent opaque identifier. The folder it sits in had no such protection.

## Decision

1. **The CDN folder is frozen when an object is first published, and it is data.**
   - `data/images.csv` gets a `cdn_folder` column. It names the folder holding the photograph's original and, under `derived/`, its derivatives. **A blank cell means the folder is named for `species_slug`**, which is what every photograph had before the column existed, so nobody has to fill it in and a hand-added row leaves it empty.
   - `data/species-photos-manifest.csv` gets a `cdn_folder` column with the same rule. It names the folder under `species-tiles/` that holds a specimen's tile pyramid and under `derived/species-tiles/` its thumbnails. `tiles_path` in `data/species-photos.json` is built from it.
   - Plates are not affected: their folders are named for the plate, not the species.
   - The rename command fills the cell in with the old slug for that species' rows. After that a rename changes `species_slug` and never `cdn_folder`, so no CDN object moves, no derivative row is re-keyed, and no password is needed.
2. **One module builds a photograph's path.** `src/_lib/photo-path.ts` is the only place that joins a folder and a filename. Templates, the build scripts and the browser components call it. A test in `npm test` scans the source for the ways this repository has joined a slug into a storage path by hand (`${slug}/${…}`, `slug + '/' + …`, `join(…, slug, …)`, `species-tiles/${…}`, `derived/${…}`) and fails on any of them outside that module. It is a pattern match and catches those forms, not every possible one. The one-off `migrate-*` scripts, which hard-code both names of a pair, are exempt.
3. **Data that reaches the browser carries the folder only when it differs from the slug.** `nav_folder` on a key-matrix species and `thumb_url` on a browse image are written only for a species that has been renamed. With every cell blank, the built site is identical to the one before this change: all 1,413 HTML, JSON, XML, CSV and text files compare equal once the hashed names of the bundled scripts are ignored.
4. **The slug stays the key between data files and the public address.** Contributors edit these CSVs by hand without a build, and a readable key is part of that. `species.csv` already has a numeric `id`, so a later switch to ids stays possible. This ADR does not do it.
5. **One command does a rename.** `npm run species:rename -- old-slug "New Genus new epithet"` re-keys the slug in every file listed in `RELATIONS` in [`check-referential-integrity.ts`](../../scripts/check-referential-integrity.ts) and in the other places a slug is embedded (records, the manifest, the exceptions file, the species page's Markdown file, the ratchet list in `check-photo-determinations.ts`). It sets `cdn_folder`, adds the redirect and a synonym row for the old name, and regenerates the checklist order and the Identify matrix. It builds every edit in memory first and writes nothing if the old slug would still appear in a file that should be free of it, then writes each file to a temporary copy and moves the copies into place only once they all exist. `DRY_RUN=1` lists what it would change. A second run changes nothing, and it says so only once no file still holds the old slug; otherwise it reports that the earlier run stopped partway. It also regenerates the hidden-images report, and it refuses a slug that is still the old address of a different species unless told `--reuse-slug`. It leaves the authority, common name and prose to people. The runbook is [`_instructions/RENAMING_A_SPECIES.md`](../../_instructions/RENAMING_A_SPECIES.md).

## Consequences

- A rename edits data files and moves nothing on the CDN. The copy scripts of #266, #303, #369 and the like are no longer needed for a rename. They stay in the repository as the record of what was done.
- `cdn_folder` becomes a rule every photograph path must follow. Because a blank cell works, a file that ignores the column keeps working until the first rename, and then shows a wrong folder rather than a 404 from a missing copy. Four guards cover this, and none is complete alone: the source scan from item 2, which catches the forms it knows; the derivatives check, which compares every row of `data/image-derivatives.csv` with the path built from `cdn_folder`, for the species the build publishes; the referential-integrity gate, which fails on a filled `cdn_folder` that is neither a species nor an old address in `data/species-redirects.csv`, withheld species included; and tests that run a renamed species through the share image, the Identify card, the derivative list and the tile path.
- No existing row is rewritten. A blank cell is the slug, which is the folder every object sits in today: each earlier rename copied the objects to the new folder. The old folders are still on the CDN, listed as leftovers in `data/cdn-retired-images.csv`.
- Two tile sets can now collide in two ways: on one account (two A-D sets for one species) or in one folder (a species renamed onto a slug that is still another species' frozen folder). `tile-photos.ts` blocks a row that collides either way. Before this ADR the slug was the folder, so one check covered both.
- A folder name that differs from the species slug is not an error. `emit-cdn-inventory.ts` accounts for objects by folder and filename, not by whether the folder is a current slug.
- A merge or a re-determination could also leave objects where they are, by giving the moved rows a `cdn_folder` that names their current folder. This ADR does not build that. The existing procedure for those still copies, and [`docs/concerns.md`](../concerns.md) lists it.

## Alternatives considered

- **Switch every join to the numeric id.** It removes the problem completely, but every CSV becomes unreadable to the people who edit them, and every file changes at once.
- **Keep re-keying by hand, with a checklist.** This is what `docs/lessons-learned.md` already is, and each rename found a new file that had been missed.
- **Make the deploy copy the photographs.** [ADR 0001](0001-static-no-server.md) keeps pipeline operations on a maintainer's machine, and the copy is the step that needs the password.
- **One folder per species instead of per photograph.** Simpler, but a merge or a re-determination (ADR 0038) leaves some of a species' photographs in another species' folder, so one value per species cannot say where they are.
- **Fill in `cdn_folder` for every existing row and make it required.** It would make a forgotten helper fail loudly. But photographs are added by hand to a CSV (`_instructions/ADDING_PHOTO.md`), and a required cell the author must copy from the slug column is one more way to get a row wrong. A blank cell that means "the slug" keeps that path unchanged.
