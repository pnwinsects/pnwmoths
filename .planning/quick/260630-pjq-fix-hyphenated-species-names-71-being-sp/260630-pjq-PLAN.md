<objective>
Fix GitHub issue #71: hyphenated species (Xestia c-nigrum, Autographa v-alba) appear as TWO pages — one at the full name and one truncated at the hyphen — with content scattered across both.

Root cause (data-level, not template): `data/species.csv` contains duplicate, hyphen-truncated rows that share the same `noc_id` as their correct full-name counterparts:
- id 2676 `Xestia,c` duplicates id 3381 `Xestia,c-nigrum` (both noc_id 93-3588)
- id 1551 `Autographa,v` duplicates id 3380 `Autographa,v-alba` (both noc_id 93-1197)

The species template (`src/species/species.njk`) paginates over the `species` data and derives each slug as `lower(genus || '-' || species)`, so each truncated row generates its own spurious page (`/species/xestia-c/`, `/species/autographa-v/`). The data is split across the two slugs: the prose account (`src/content/species/xestia-c-nigrum.md`) attaches to the full slug, while all 458+52 occurrence records (`data/records.csv`), 6 photos (`data/images.csv`), and one `similar_species` link still point at the truncated slug — so neither page is complete. This is a residue of the original MySQL→CSV migration that split the epithet at the hyphen; the correct full rows were added later (ids 3380/3381) but the truncated originals and their record/image keys were never cleaned up. The original WWU site's inbound URLs use the full names (confirmed in `redirect-analysis.md`), so the full slug is canonical.

Fix: consolidate each species onto its canonical full slug by deleting the truncated `species.csv` rows, re-keying the records/images to the full slug, repointing the similar_species link, pruning the redirect allow-list, and additively re-uploading the 6 photos to the full-slug CDN folder.

Purpose: One correct page per hyphenated species, with prose + occurrence map + phenology + photos all present.
Output: Edited `data/species.csv`, `data/records.csv`, `data/images.csv`, `src/_data/speciesSlugs.json`; 6 photos re-uploaded to the new CDN folders.
</objective>
