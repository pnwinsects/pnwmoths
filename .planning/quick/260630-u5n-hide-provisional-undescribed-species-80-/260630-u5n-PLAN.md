<objective>
Hide the 20 confirmed provisional/undescribed morphospecies (GitHub #80 — "Aseptis sp No 1" et al.) from every reader-facing surface — species pages, Browse, Pagefind search, and Identify — via a data-driven build-time deny-list that exactly mirrors the existing `withheld-families` gate. This is a DISPLAY deny-list, not a data deletion: their occurrence records, images, per-species parquet, and Lucid key source stay untouched, and any species is re-included by deleting its line from `data/unpublished-species.csv`.

Purpose: The Eleventy build paginates one page per `data/species.csv` row, so provisional morphospecies that carry specimen records but have no published reference-site factsheet leak into pages/Browse/search. The reference site only ever published species present as leaves in its CMS browse tree; these 20 are not. Filter them at the SAME four choke points the family-withholding gate uses.

Output: `data/unpublished-species.csv` (deny-list), `src/_lib/unpublished-species.ts` (shared loader/predicate + tests), the deny-list wired into `species.ts`/`taxon.ts`/`build-key.ts`/`stats.ts`, and a new `scripts/check-unpublished.ts` build-time leak gate + tests, registered in the build and test npm scripts.
</objective>

<grounding_facts>
Verified against the working tree during planning — DO NOT re-investigate these:

1. Four choke points apply `isWithheldOrUnclassified` today; this deny-list must sit beside each:
   - `src/_data/species.ts` — paginated species pages AND (transitively) the Pagefind search index, since Pagefind indexes only emitted `_site/**` HTML. Loop filter at ~line 84.
   - `src/_data/taxon.ts` — Browse tree. Row push guard at ~line 163.
   - `scripts/build-key.ts` — Identify / `data/key-matrix.json`. `siteSlugSet` is built from a filtered `speciesRows` at ~line 230; a species absent from `siteSlugSet` resolves to `null` and is excluded from the emitted matrix.
   - `src/_data/stats.ts` — home-page vanity counts. `shown` CTE WHERE clause at ~line 50 (already injects an escaped `withheldList`).

2. Slug-format quirk (critical). The site slug is `lower(genus || '-' || species)`. For 13 of the 20 the `species` field contains spaces, so the RAW emitted slug has spaces (e.g. Aseptis / "sp No 1" produces `aseptis-sp no 1`; Eleventy emits the directory `_site/species/aseptis-sp no 1/`). The deny-list slugs are hyphenated (`aseptis-sp-no-1`). Matching therefore REQUIRES whitespace-to-hyphen normalization: trim, lowercase, then replace `/\s+/g` with `-`. All 20 deny-list slugs normalize exactly from their species.csv rows (verified). The other 7 (drasteria-sp, fishia-sp, holoarctia-sp, leucania-sp, mniotype-sp, pseudanarta-sp, aseptis-species) are already hyphen-clean.

3. Current state (baseline to fix): all 20 currently emit `_site/species/<slug>/` directories. `data/key-matrix.json` currently contains 0 of the 20 (none appear in the Lucid source `data/key-characters.csv` at all) — so the build-key filter is a defensive/future-proofing mirror, and the check gate's key-matrix arm is a regression guard, not a current-leak fix.

4. Preservation targets (must stay unchanged): `data/records.csv` has 34 rows and `data/images.csv` has 19 rows for these 20 slugs; `data/parquet/<raw-slug>/records.parquet` dirs exist (built by build:data from records.csv). This plan touches NONE of records.csv, images.csv, key-characters.csv, build-data.ts, or data/parquet/.

5. `similar_species` cross-refs are self-healing. species.njk renders a similar-species entry only if the referenced slug is found in the (now-filtered) `species` collection; a deny-listed sibling is silently skipped — no broken links, no extra work (matches the WR-01 record-only precedent).

6. Toolchain: Node 24 native type-stripping (run `.ts` directly), node:test, csv-parse/sync. The `test` npm script globs `src/_lib/*.test.ts` and `src/_data/*.test.ts` (new tests there auto-run) but lists `scripts/*.test.ts` files individually (the new gate test must be added explicitly).
</grounding_facts>
