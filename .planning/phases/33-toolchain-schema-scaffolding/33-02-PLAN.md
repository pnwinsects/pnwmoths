<objective>
Author the Zod 4 schema module for all seven data entities, derive their TypeScript types via `z.infer<>`, and prove every schema accepts all real production data — then confirm no regression (no enums, existing `.js` build still emits 1,364 species pages).

Purpose: These schemas are the single source of truth for every data contract in the v3.0 migration. Build-side consumers (Phases 34–36) import only the *derived types* (zero runtime cost); the *validators* are wired at the two dynamic CDN load points in Phase 37. Grounding the schemas in the profiled null distribution (SCHEMA-03 / D-08) is the gate that prevents an over-strict schema from hard-blocking the build (Pitfall 2: `county` is 100% null — a non-nullable `county` would reject all 92,554 records).

Output: `src/types/schemas.ts` (seven schemas + derived types), `src/types/index.ts` (re-exports), `scripts/profile-data.ts` (acceptance harness), and a committed `DATA-PROFILE.md` null-distribution note for non-technical maintainers.
</objective>
