<objective>
Convert `eleventy.config.js` → `eleventy.config.ts` and lay the Eleventy `.ts`-loading mechanism that the per-file data conversions (Plans 02, 03) depend on. This is the keystone plan: until Eleventy can load a `.ts` config and discover `.ts` global data files, no data file can be safely renamed.

Three Eleventy-discovery facts (verified in 36-RESEARCH.md by direct source inspection of `@11ty/eleventy` 3.1.5) drive this plan:
1. Eleventy does NOT auto-discover `eleventy.config.ts` — its search list is hardcoded to `.eleventy.js`/`eleventy.config.{js,mjs,cjs}`. Fix: add `--config=eleventy.config.ts` to `build:eleventy` and `dev`. This is a built-in CLI flag, NOT a loader (honors the milestone loader-free thesis, Phase 38 SC-2).
2. Eleventy does NOT auto-discover `.ts` global data files — `getGlobalDataExtensionPriorities()` returns only `["json","mjs","cjs","js"]`. Fix: register `addDataExtension("ts", { read: false, parser })` whose parser `import()`s the file and explicitly invokes the default-export function.
3. Node 24 native type-stripping (`process.features.typescript === 'strip'`, confirmed) handles `import("file.ts")` with no flags.

This plan also lands the Wave 0 tooling/test items (per 36-VALIDATION.md): rename+extend the config test, fix the `tsconfig.node.json` include gap, update the `package.json` test glob and build scripts.

Purpose: MIG-03 — preserve the `GITHUB_PAGES`-conditional `pathPrefix` (SC-2/SC-3), make Eleventy load the `.ts` config and `.ts` data files (SC-1), repair the broken `.js` execFile references left by Phase 35, and keep `_site/` byte-identical (SC-4).

Output: `eleventy.config.ts`, `eleventy.config.test.ts`, updated `tsconfig.node.json` and `package.json`; `eleventy.config.js` and `eleventy.config.test.js` deleted.
</objective>

| config → data files | `addDataExtension("ts")` parser dynamically `import()`s `src/_data/*.ts`. Imported paths are Eleventy-glob-discovered repository files — not external input. |
| build → filesystem | Config module init reads `data/glossary.csv` (committed repo data). No network, no untrusted input. |

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-36-01 | Tampering | `execFile("node", ["scripts/*.ts"])` child spawn | accept | Paths are hardcoded repository-relative string literals (no interpolation, no user input). `execFile` (not `exec`) does not invoke a shell. Pattern pre-exists from prior phases; this plan only repoints `.js`→`.ts`. No high-severity surface. |
| T-36-02 | Tampering | `addDataExtension` parser `import(filePath)` executing data-file default exports at build | accept | `filePath` is supplied by Eleventy's own glob discovery over `src/_data/` (committed repo files only). | T-36-SC | Tampering | npm/pip/cargo installs | mitigate | No packages installed this phase (36-RESEARCH §Package Legitimacy Audit: "No new packages"). No install task exists; gate is N/A. |

This is a build-time/config-only TypeScript migration. Nothing ships to the browser bundle; no new runtime input surface is introduced. No ASVS L1 category applies (RESEARCH §Security Domain). No high-severity threats found.
