## Typography

Source: Phase 41 UI-SPEC (inherited). Same four roles, same values.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body / card common name | 16px (1rem, Pico default) | 400 | 1.5 |
| Small label (count line, prompt, empty-state text) | 14px (0.875rem) | 400 | 1.4 |
| Card binomial (`<em>`) | 14px (0.875rem) | 400 italic | 1.3 |
| Page heading `<h1>` | 28px (~1.75rem) | 600 | 1.2 |

Notes:
- The card binomial is rendered as `<em>${genus} ${epithet}</em>`. It inherits body font (Open Sans) with italic styling applied by the `<em>` element. No separate font-style declaration needed.
- The common name (when non-null) renders on its own line below the binomial at **16px, weight 400** (standard body). It uses `<br>` between the `<em>` tag and the text — no separate wrapper element needed.
- The count line is a `<p class="pnwm-krg-count">` at **14px**. It is visually subordinate to the content; it does not use a heading element.
- The at-rest prompt and the zero-match message are `<p>` elements at **14px, weight 400, muted color** (`color: var(--pico-muted-color)` or `#888`).

## Layout

Source: 42-CONTEXT.md decisions D-04, D-05; 42-RESEARCH.md Pattern 5.

### Two-column page layout (desktop — D-04)

```
pnwm-identify (Light DOM)
  <div class="pnwm-identify-layout">
    <aside class="pnwm-identify-panel">
      [sticky "Clear all" bar — Phase 41]
      [8 category accordions — Phase 41]
    </aside>
    <div class="pnwm-identify-grid-area">
      <key-results-grid ...></key-results-grid>
    </div>
  </div>
```

CSS (add to `theme.css`):

```css
/* Two-column layout for /identify/ — desktop */
.pnwm-identify-layout {
  display: grid;
  grid-template-columns: 280px 1fr;
  gap: 24px;
  align-items: start;
}

/* Panel column: sticky while grid scrolls */
.pnwm-identify-panel {
  position: sticky;
  top: 0;
  max-height: 100vh;
  overflow-y: auto;
  align-self: start;
  min-width: 0;
}

/* Grid area: flex column, count line pinned above grid */
.pnwm-identify-grid-area {
  min-width: 0;
}

/* Collapse to stacked at ≤ 768px */
@media (max-width: 768px) {
  .pnwm-identify-layout {
    grid-template-columns: 1fr;
    gap: 16px;
  }
  .pnwm-identify-panel {
    position: static;
    max-height: none;
    overflow-y: visible;
  }
}
```

**Panel column width:** 280px fixed on desktop. This is wide enough for question labels (the longest: "Distribution" / "Forewing color and pattern") and the accordion chevron + badge without overflow. The panel is narrower than the species-page two-column (which uses `1fr 1fr`) to give more room to the grid.

**Breakpoint:** 768px — same as `.species-content` breakpoint in `theme.css` (line 262). Collapses to single column (panel on top, grid below). Plain stack, no drawer toggle (see Mobile section).

**Sticky panel top offset:** `top: 0`. The site header scrolls away (it is not `position: sticky`), so `top: 0` correctly pins the panel to the viewport top once the header has scrolled off. `max-height: 100vh; overflow-y: auto` enables internal scrolling for the long 237-state panel on short viewports.

### Mobile / narrow layout (D-05 — stack, no drawer)

Baseline stack is the contracted behavior. A "Filters" drawer toggle is explicitly out of scope for this phase (D-05 deferred it as a "maybe"; researcher recommendation is to leave it for v4.x). The default-collapsed categories keep the panel compact on mobile — all 8 categories collapsed = ~8 `<h2>` rows, comfortably short.

No new drawer affordance, toggle button, or offcanvas pattern is introduced in this phase.

### Count line placement

The count line is the **first child** of `<key-results-grid>`'s render output, always visible above whatever grid state is active (prompt, grid, or empty-state). It is part of `key-results-grid`'s render method, not a sibling element in `pnwm-identify`. This keeps the count co-located with the thing it describes.

CSS for the count line:

```css
.pnwm-krg-count {
  font-size: 0.875rem;   /* 14px */
  color: var(--pico-muted-color);
  margin: 0 0 8px 0;
  padding: 8px 0 0 0;
}
```

## Grid Anatomy

**Primary visual anchor:** the thumbnail card grid is the dominant element of the results column — the 160px-tall photo thumbnails are what the eye lands on first and what communicates the filtered result set at a glance. The count line above it is intentionally subordinate (14px, muted), and the panel is a secondary control surface. Everything below describes that anchor.

### Grid container

```css
.pnwm-krg-grid {
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(140px, 1fr));
  gap: 16px;
}
```

- `minmax(140px, 1fr)`: at the grid column's full width (~820px with a 280px panel and 24px gap in a 1140px content-wrapper), this yields approximately 5–6 columns. At 600px grid width it yields ~4 columns. At ≤400px (narrow mobile) it yields ~2–3 columns. Behavior is fully responsive with no breakpoint media queries inside the grid.
- `gap: 16px` (1rem) — mirrors taxon-browser's `.pnwm-tb-species-grid { gap: 1rem }`.
- No fixed column count. `auto-fill` with `minmax` adapts gracefully across all viewport sizes.

### Card anatomy

Each card is an `<a class="pnwm-krg-card">` element. Stacking order from top to bottom:

1. **Thumbnail `<img>`** — fills card width, fixed height 160px, `object-fit: cover`.
   OR
   **Placeholder `<div class="similar-species-placeholder">`** — the existing 93px × 60px gray block (reused as-is from `theme.css`). For placeholder-only cards the card height is shorter than image cards; this is acceptable. The gray block is centered horizontally within the card via `display: flex; align-items: center; justify-content: center` on the card's image container.

2. **Label `<div class="pnwm-krg-label">`** — contains:
   - `<em>${genus} ${epithet}</em>` — italic binomial, 14px, weight 400
   - Conditional: `<br><span class="pnwm-krg-common">${common_name}</span>` — only when `common_name` is non-null; 16px, weight 400

CSS:

```css
.pnwm-krg-card {
  display: block;
  text-decoration: none;
  color: inherit;
}

.pnwm-krg-card:hover,
.pnwm-krg-card:focus-visible {
  outline: 2px solid var(--pico-primary);
  outline-offset: 2px;
  border-radius: 2px;
}

.pnwm-krg-card img {
  width: 100%;
  height: 160px;
  object-fit: cover;
  display: block;
  border-radius: 2px;
}

/* Placeholder container — centers the gray block within card width */
.pnwm-krg-placeholder-wrap {
  display: flex;
  align-items: center;
  justify-content: center;
  height: 160px;       /* matches image height for even grid rows */
  background: #f0ece0; /* slightly lighter than placeholder fill — visible boundary */
  border-radius: 2px;
}

/* .similar-species-placeholder already in theme.css — do NOT redefine height/width/bg.
   Key-results-grid uses it as-is inside .pnwm-krg-placeholder-wrap. */

.pnwm-krg-label {
  padding: 4px 0 0 0;
  font-size: 0.875rem;   /* 14px for binomial */
  line-height: 1.3;
}

.pnwm-krg-common {
  font-size: 1rem;       /* 16px for common name */
  font-style: normal;
  display: block;
  line-height: 1.4;
  margin-top: 4px;
}
```

**Thumbnail height: 160px (not 186px)**. The taxon-browser uses `?height=186` on the CDN request and displays the image at `height: 93px` (half of request height for 2x DPR). The results grid requests `?height=320` from the CDN to support 2x DPR at 160px display height. The CDN `?height=` parameter is a resize hint, not the display height. The display height is set by CSS at `height: 160px`.

CDN URL pattern (prescribed):
```
${CDN_BASE_URL}/${sp.slug}/${encodeURIComponent(sp.nav_image)}?height=320
```

- `CDN_BASE_URL = 'https://pnwmoths.b-cdn.net'` — hardcoded const in the component module, same as taxon-browser.
- `loading="lazy"` on every `<img>`.
- `alt="${sp.genus} ${sp.epithet}"` — provides screen-reader text for the image.

## States and Copywriting Contract

There are **three mutually exclusive grid area states**. The count line is present in all three.

### State 1: At-rest (no selection — D-02, D-03)

Condition: `hasSelection === false`

Count line text: **"Showing all 1,192 species"**
Grid area content: a prompt paragraph

```
Showing all 1,192 species
Select characters to narrow the 1,192 key species
```

CSS class for prompt: `.pnwm-krg-prompt { font-size: 0.875rem; color: var(--pico-muted-color); margin: 16px 0; }`

### State 2: Active filter, results found

Condition: `hasSelection === true && matchedSpecies.length > 0`

Count line text: **"${count} species match"**
Grid area content: the `pnwm-krg-grid` with cards

Note: "species match" (not "species found" or "results") — matches D-01 locked copy exactly.

### State 3: Zero-match empty state (D-09, GRID-04)

Condition: `hasSelection === true && matchedSpecies.length === 0`

Count line text: **"0 species match"** (uses the same pattern as state 2; count is 0)
Grid area content: empty-state message + "Clear all" CTA

```
No species match the selected characters
[Clear all]
```

CSS class for empty-state message: `.pnwm-krg-empty { font-size: 0.875rem; color: var(--pico-muted-color); margin: 16px 0; }`

The "Clear all" CTA button in state 3:
- Same Pico primary button style as the panel's existing "Clear all" (olive background `#a4ab78`, white text).
- Label: **"Clear all"** — identical to the panel button (one consistent affordance across both locations).
- Mechanism: dispatches bubbling `pnwm-key-clear-all` CustomEvent; `pnwm-identify` handles it via `@pnwm-key-clear-all=${() => this._clearAll()}` in its render template.
- This is the same reset path as the panel's "Clear all" (D-09 — single source of truth).

### State 4: Matrix load failed (error state)

Condition: `pnwm-identify` fetch failed (network error or `validateKeyMatrix()` threw)

Count line text: **"Showing all 1,192 species"** (at-rest fallback)
Grid area content: prompt (same as at-rest — grid stays inert, panel remains interactive)

No explicit error message shown to the user. The error is logged to `console.error` only. The rationale: the panel is still interactive (characters list is inlined from Phase 41); only the live count and thumbnail grid are unavailable. A red error banner would alarm users unnecessarily. Source: 42-RESEARCH.md Pattern 1 note "soft degradation: grid stays in 'prompt' state".

## Accessibility Contract

Source: design_context accessibility requirements + WCAG 2.1 AA baseline.

### Count line aria-live

The count line element carries `aria-live="polite"` and `aria-atomic="true"` so screen reader users hear the updated count after each selection change without interrupting in-progress speech.

```html
<p class="pnwm-krg-count" aria-live="polite" aria-atomic="true">
  ${count} species match
</p>
```

This satisfies GRID-01 ("count updates on every selection change") for assistive technology users.

### Card link labelling

Each card is an `<a href="...">` containing an `<img alt="${genus} ${epithet}">` (or the placeholder `aria-hidden` div) and the label text. The link's accessible name is derived from the image alt text + the label text content. Because the `<em>` binomial is inside the link, screen readers announce it naturally. No `aria-label` attribute is needed unless testing reveals ambiguity.

### Focus order

Focus order: filter panel checkboxes (Phase 41) → count line (skipped — not focusable) → grid cards. Cards receive focus via Tab in DOM order (left-to-right, top-to-bottom in visual grid layout). No `tabindex` manipulation needed.

The sticky panel has `overflow-y: auto` which creates its own scroll context. Focus management within the panel is handled by Phase 41.

### Lazy-loaded images

All grid card `<img>` elements use `loading="lazy"`. The browser handles deferral; no JS intersection observer is needed. Images that are in the viewport on initial grid render (after first selection) load eagerly per browser heuristics even with `loading="lazy"`.

### Keyboard interaction for "Clear all" in empty state

The empty-state "Clear all" is a `<button type="button">`. Keyboard activation (Enter or Space) dispatches the same `pnwm-key-clear-all` event as a click. No additional keyboard handling needed.

### No-JS degradation

Grid is JS-only. Phase 41's `<noscript>` block provides the static species list. No action needed in this phase.

## Interaction Contract

| Interaction | Trigger | Result |
|-------------|---------|--------|
| First character state selected | Checkbox click in panel | `pnwm-identify._dispatchFilterChange()` calls `computeMatching()`; `_matchedSpecies` and `_matchedCount` set; `key-results-grid` re-renders with matching cards; count line updates to "N species match"; aria-live region announces new count |
| Character state deselected | Checkbox click (checked → unchecked) | Same as above; matching re-computed; grid updates; count updates |
| All states deselected (returns to at-rest) | Last checkbox unchecked | `hasSelection` → `false`; grid returns to prompt state; count → "Showing all 1,192 species" |
| "Clear all" (panel sticky button — Phase 41) | Click panel's "Clear all" | `pnwm-identify._clearAll()`: all checkboxes unchecked, `_matchedSpecies = []`, `_matchedCount = 0`, `_hasSelection = false`; grid returns to prompt; count → at-rest |
| "Clear all" (empty-state CTA — this phase) | Click empty-state button | Dispatches `pnwm-key-clear-all`; `pnwm-identify` handles via `@pnwm-key-clear-all`; same outcome as panel "Clear all" |
| Card click | Click any `<a class="pnwm-krg-card">` | Browser navigates to `/species/{slug}/` (full page navigation) |
| Card hover | Pointer enters card | `outline: 2px solid var(--pico-primary)` on the `<a>` element |
| Card focus-visible | Keyboard Tab to card | Same outline as hover |
| Matrix fetch fails | Network error / validation error | Grid stays in at-rest prompt state; error logged to console; no user-visible error message |
| Page load (JS) | `connectedCallback` in `pnwm-identify` | Reads inline `#key-char-data` (Phase 41); kicks off async `fetch('${prefix}key-matrix.json')`; grid renders at-rest prompt; count shows "Showing all 1,192 species" |
