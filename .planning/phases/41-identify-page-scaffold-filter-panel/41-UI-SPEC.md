## Layout

Source: 41-CONTEXT.md decisions D-03, D-05, D-06; REQUIREMENTS.md IDENT-02, IDENT-06.

### Page layout

The `/identify/` page uses `base.njk` (cream background, white `.content-wrapper` card, max-width 1140px). No two-column layout in this phase — the filter panel is a single full-width panel within the content wrapper. The results grid (Phase 42) will sit below or beside the panel.

### Filter panel structure

```
pnwm-identify (Light DOM root component)
  [sticky bar]
    "Clear all" button — visible only when ≥1 state is selected
  [8 category sections, default-collapsed]
    <div class="pnwm-kfp-category">
      <h2>
        <button type="button" aria-expanded="false">
          Distribution
          [badge: "(3)" if selections > 0]
        </button>
      </h2>
      <div hidden>
        [for each question in category]
          <fieldset class="pnwm-kfp-question">
            <legend>{question text}</legend>
            [for each state in question]
              <label>
                <input type="checkbox"> {state text}
              </label>
          </fieldset>
      </div>
```

Key structural rules:
- Light DOM only (`createRenderRoot() { return this; }`) — Pico CSS must reach checkboxes, labels, fieldsets.
- `pnwm-identify` is the parent host; `character-filter-panel` may be a separate Lit element or rendered within `pnwm-identify`'s render method (implementation discretion, per 41-CONTEXT.md).
- The 8-category expand/collapse follows the exact `aria-expanded` toggle pattern from `pnwm-taxon-browser`: `new Set` reactivity, `?hidden=${!expanded}` on content div.
- `<fieldset>/<legend>` groups each question's checkboxes for semantic grouping (the OR-within-question boundary that drives `buildQuestionGroups()` must be visually and semantically explicit).
- "Clear all" sticky at the top of the scroll container: `position: sticky; top: 0; z-index: 1; background: #ffffff;` within `.content-wrapper`.

### No-JS degradation (`<noscript>`)

Two blocks inside `<noscript data-pagefind-ignore>`:
1. Character hierarchy as nested plain text (no form controls):
   - Category heading → question text → state text, using `<h2>`, `<h3>`, `<ul>/<li>` — no `<input>` elements.
2. Full 1,192 matched species as links, grouped Family → Genus (mirrors Browse `<noscript>` pattern exactly).

## Inline JSON Strategy

Source: 41-CONTEXT.md "Claude's Discretion — Inline-JSON scope".

Decision (researcher): Inline the **character hierarchy** only — not the bitset matrix.

- What: `key-matrix.json` `.characters` array (237 character objects with `category`, `subcategory`, `question`, `state`, `id`) inlined as `<script type="application/json" id="key-char-data" data-pagefind-ignore>`.
- Why: The panel needs only the hierarchy to render. Bitsets (~29 KB gzip) are needed only for `computeMatching()`, which is Phase 42's concern.
- Size check: 237 character objects at ~100 bytes each = ~24 KB raw JSON, well under page-weight budget when inlined.
- How: An Eleventy `_data` loader (e.g. `src/_data/keyMatrix.ts`) reads `data/key-matrix.json` and exports `{ characters, species }`. The template inlines `characters` as `#key-char-data` and uses `species` for the no-JS family-grouped species list.
- The `pnwm-identify` component reads `document.getElementById('key-char-data')?.textContent` synchronously in `connectedCallback`, mirroring the `#taxon-data` pattern in `pnwm-taxon-browser`.

## Interaction Contract

| Interaction | Trigger | Result |
|-------------|---------|--------|
| Expand category | Click category `<button aria-expanded="false">` | `aria-expanded` → `"true"`, content div `hidden` removed, arrow rotates 90° |
| Collapse category | Click category `<button aria-expanded="true">` | `aria-expanded` → `"false"`, content div gets `hidden`, arrow rotates back |
| Select a state | Click checkbox | Checkbox checked, category badge count increments, `pnwm-key-filter-change` dispatched (no consumer yet in Phase 41 — event is produced but ignored) |
| Deselect a state | Click checked checkbox | Checkbox unchecked, badge count decrements (or badge hidden if 0), `pnwm-key-filter-change` dispatched |
| "Clear all" | Click "Clear all" button | All checkboxes unchecked, all badge counts → 0, badges hidden, `pnwm-key-filter-change` dispatched with `{ matchedSlugs: allSlugs, count: 1192, hasSelection: false }`, "Clear all" button hides |
| Page load (JS) | `connectedCallback` | Character hierarchy read from `#key-char-data`, panel rendered with 8 collapsed categories; `pnwm-key-filter-change` NOT dispatched on initial load (no selection yet) |
| Page load (no JS) | Static HTML | `<noscript>` block visible: character list as nested text + species as links |

## Accessibility Contract

- All 8 category headings are real `<h2>` elements containing the toggle `<button>`, mirroring the taxon browser. `aria-expanded` is kept accurate.
- Each question group is a `<fieldset>` with `<legend>` so screen readers announce the question before its checkboxes.
- "Clear all" button: `aria-live` region is NOT required in this phase (the results count is Phase 42). The button itself needs no additional ARIA.
- Keyboard: Tab to reach category buttons and checkboxes; Enter/Space to toggle (native button/checkbox behavior).
- The `▶` triangle is decorative (`content:` CSS only, not in DOM text).
- `data-pagefind-ignore` on the inline JSON `<script>` block and the `<noscript>` section to keep the Pagefind index clean (mirrors browse page).
