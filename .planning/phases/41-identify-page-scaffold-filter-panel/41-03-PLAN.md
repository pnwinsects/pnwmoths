<objective>
Build the `pnwm-identify` Light-DOM Lit component that reads the inlined `#key-char-data`, renders 8 default-collapsed collapsible categories (each question a `<fieldset>/<legend>` group of per-state checkboxes), tracks selection with per-category count badges, provides a conditionally-visible sticky "Clear all" reset, and dispatches `pnwm-key-filter-change` on every change. Register it in `main.ts` and add the `.pnwm-kfp-*` styles. Tests come first (TDD).

Purpose: IDENT-02 (collapsible 8-category panel reusing the `pnwm-taxon-browser` `aria-expanded` pattern), IDENT-03 (select/deselect in any order, reflected in real time via badges), and IDENT-05 ("Clear all" restores the full set). The hard logic (filter semantics, bitset decoding, slug matching) already lives in `src/_lib/key-filter.ts` and is NOT exercised here — Phase 41 dispatches the event with placeholder `matchedSlugs: []`; the consuming results grid is Phase 42. This is UI composition mirroring `pnwm-taxon-browser` exactly: Light DOM (`createRenderRoot() { return this; }`), new-Set/new-Map reactivity, `?hidden=${!expanded}` content toggling.

Output: `src/components/pnwm-identify.ts`, `src/components/pnwm-identify.test.ts`, a one-line addition to `src/components/main.ts`, and `.pnwm-kfp-*` rules in `src/styles/theme.css`.

Decisions implemented: D-01/D-02 (all 8 categories, Distribution flat — no special-casing), D-03 (category-only collapse, default-collapsed; questions are fieldset/legend groups, not individually collapsible), D-04 (categories rendered in native key order as read from the inline JSON), D-05 (per-category selection-count badges), D-06 (sticky 'Clear all', visible only when ≥1 state selected).
</objective>
