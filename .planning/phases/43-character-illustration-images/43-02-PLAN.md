<objective>
Deliver CIMG-01 (the idempotent CDN uploader) and the data half of CIMG-02 (the committed draft mapping CSV). `scripts/upload-images.ts` is a near-verbatim clone of `scripts/upload-tiles.ts` minus the manifest: it walks the local Lucid key media (D-01), keeps only the ~197 genuine character illustrations (D-02; layered filter — RESEARCH Pitfall 4), converts each to WebP at original dimensions via `vips` (D-03), and PUTs to `key-images/` on the bunny Storage Zone (D-04). `scripts/match-character-images.ts` is a one-off that normalizes `key-matrix.json` state names against the kept filenames and writes the committed draft `data/key-character-images.csv`, one row per `char_id` (D-05, D-07).

A single canonical `toWebpName()` helper, exported from the uploader and imported by the matcher, guarantees the `.jpg`→`.webp` name never drifts across CSV / CDN object / `<img src>` (RESEARCH Pitfall 6).

Purpose: Get the character images onto the CDN idempotently and produce the curator's starting-point CSV.
Output: Two scripts + their tests, a committed draft CSV (~77 exact-normalized rows per RESEARCH), and the WebP objects live under `key-images/` on the CDN (via the human checkpoint).

Note on CIMG-01 "resize appropriately" (requirement wording) vs D-03 (locked decision): the requirement's "resized appropriately" is intentionally delivered as **no server-side resize** — each source JPEG is converted to WebP at its ORIGINAL dimensions (D-03), and in-panel sizing is handled client-side by a CSS `max-height: 320px` cap (UI-SPEC §3, applied in Plan 03). D-03 post-dates and overrides the requirement's resize wording; the SUMMARY for this plan MUST record this requirement-vs-decision delta for auditability.

Interface-first ordering: Task 1 defines the exported helpers (`isCharacterIllustration`, `toWebpName`, storage-URL builder) inside the uploader; Task 2 (the matcher) imports `toWebpName` from the uploader; Task 3 (the checkpoint) runs the real upload. No cross-plan file dependency — both scripts live in this plan.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator env → curl | `BUNNY_API_KEY` enters via env; flows into curl `AccessKey` headers. Untrusted only if logged. |
| local filesystem → vips/curl child_process | Source image filenames (with spaces, punctuation) are passed to `vips` and `curl` as argv. |
| bunny CDN → (downstream render) | Uploaded object names become `<img src>` filenames consumed in Plan 03. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-43-02 | Information Disclosure | `BUNNY_API_KEY` in upload logs/errors | mitigate | Copy `redact()` from upload-tiles.ts:73-77 verbatim; route every log/error string through it. Key comes from env only, never committed/hardcoded (RESEARCH Security Domain V6). |
| T-43-03 | Tampering / Elevation | Shell injection via image filenames containing spaces/quotes passed to vips & curl | mitigate | Use `execFileSync` with an argv ARRAY (never a shell string) for both vips and curl, exactly as tile-photos.ts:250-253 / upload-tiles.ts:321-328. argv form treats each filename as one discrete argument — no shell parsing of spaces/quotes. |
| T-43-04 | Tampering | Specimen photos masquerading as illustrations get uploaded | mitigate | Layered filter `isCharacterIllustration` (case-insensitive ext + SPECIMEN_RE + explicit 6-file EXTRA_EXCLUDES); unit-tested against all 6 known leaks (RESEARCH Pitfall 4). | T-43-05 | Tampering | CSV injection via future curator alt_text (`=`,`+`,`@`) when matcher writes the CSV | mitigate | Write via `csv-stringify/sync` which auto-quotes (manifest.ts precedent, RESEARCH Pitfall 7). The matcher emits blank alt_text, so no live injection here; the quoting protects the curator's later hand-edits. |
| T-43-SC | Tampering | npm/pip/cargo installs | accept | Zero new package installs (RESEARCH Package Legitimacy Audit). All tooling (`vips`, `curl`) is system-level; all libs (`csv-stringify`) pre-existing. No supply-chain checkpoint required. |
