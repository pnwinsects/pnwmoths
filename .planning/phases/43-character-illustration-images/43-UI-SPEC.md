# Phase 43 — UI Design Contract

> Visual and interaction contract for the per-state character-illustration `<details>/<summary>`
> expander added to the existing `/identify/` filter panel. Generated by gsd-ui-researcher,
> verified by gsd-ui-checker.
>
> **Scope:** This is an additive micro-feature on an existing, shipped panel
> (`src/components/pnwm-identify.ts`, `_renderQuestion()`). It does NOT introduce a new page,
> new layout, new typography scale, or new color. It mirrors the established `pnwm-kfp-*`
> conventions and the project's existing Pico CSS theme (`src/styles/theme.css`). All tokens
> below are pre-existing site tokens, confirmed by reading the codebase — this spec re-states
> them so the planner/executor have a single contract, and only *adds* the small set of new
> rules the expander needs.

## Spacing Scale

Site uses an effective 4px-multiple scale (Pico `rem`-based + explicit px in `theme.css`).
Re-stated here as the contract; the expander only consumes `xs`–`md`.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Glyph-to-text gap in summary, image top offset |
| sm | 8px | Summary vertical padding, gap below state label |
| md | 16px | (existing) panel/grid gaps |
| lg | 24px | (existing) layout column gap, content-wrapper padding |

**Expander-specific spacing (new):**
- `<details>` indents to align under its state `<label>` text: `margin: 4px 0 8px 1.5em` (the
  `1.5em` matches the visual indent of the checkbox label text within the fieldset).
- `<summary>` hit area: `padding: 4px 0` (keeps the keyboard/click target ≥ 24px tall with
  the line-height, without looking like a button).
- Open image block: `margin-top: 8px`.

Exceptions: none (all values are 4px multiples).

## Typography

No new type scale. The expander reuses existing panel sizes. `<summary>` is rendered smaller
and muted so it does NOT read as another selectable character state.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body / state label (existing) | 16px (1rem) | 400 | 1.5 |
| Summary affordance (new) | 14px (0.875rem) | 400 | 1.4 |
| Image caption / alt fallback (visual) | n/a — alt text only, not rendered as visible caption | — | — |

- Summary text is `0.875rem`, weight 400 — matches existing muted panel text
  (`.pnwm-krg-count`, `.pnwm-kfp-badge` scale), deliberately one step below the 16px state
  label so the eye reads it as a secondary action, not a third checkbox option.
- Weights used in this phase: **400 only** (no bold introduced).

## Color

No new colors. 60/30/10 split is the established site contract (`theme.css`); the expander
uses only the existing cream surface, olive accent, and muted greys.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#f3e8ba` (cream, page bg) / `#ffffff` (content-wrapper + sticky panel surface) | Page background and the white panel/card surfaces |
| Secondary (30%) | `#f0ece0` / `#d6d0bc` (existing placeholder/tint greys) | Subtle tints — used here for the open image block background |
| Accent (10%) | `#a4ab78` olive (`--pico-primary`), hover `#7f8956` | Focus outlines, hover state of the summary affordance, the `ⓘ` glyph |
| Destructive | none | No destructive action in this phase |

**Accent reserved for (this phase only):**
- The `ⓘ` glyph color and the summary text `:hover` / `:focus-visible` color (`--pico-primary`).
- The keyboard focus outline on `<summary>` (`outline: 2px solid var(--pico-primary)`,
  matching `.pnwm-krg-card:focus-visible`).

Accent is NOT applied to the resting summary text (it stays muted grey `var(--pico-muted-color)`)
so a closed expander never competes visually with a selectable state or a selected `(N)` badge.

**Open image block surface:** very light cream tint `#f0ece0` (the existing grid-placeholder
tint) at `border-radius: 2px` (matches `.pnwm-krg-*` radius) — provides a quiet frame for the
illustration without a heavy border. A single hairline `border-left: 2px solid #d6d0bc` may be
used to tie the open panel to its state row (optional; executor's call within these tokens).

## Copywriting Contract

This phase has **no primary CTA, no form submit, no empty/error page, and no destructive action.**
The only new copy is the expander affordance label and the alt-text rule.

| Element | Copy |
|---------|------|
| Primary CTA | not applicable (no new CTA this phase) |
| Summary affordance label | `ⓘ illustration` (glyph `ⓘ` U+24D8 + lowercase word "illustration"). Lowercase, no trailing punctuation. Open state reads identically — the native disclosure triangle conveys open/closed; do NOT swap to "Hide illustration" text. |
| Empty state | not applicable — a state with **no** mapped image renders NO expander at all (no placeholder, no "no image" text). Panel looks exactly as it does today. (D-08 soft-degrade.) |
| Error state (image fails to load) | No visible error text. The `<img>` simply fails silently within the open `<details>`; the broken-image affordance is acceptable for this best-effort feature. Do NOT add JS error handling or fallback copy. |
| Destructive confirmation | not applicable |

**Alt-text rule (CIMG-02 / D-06):**
- `alt` = curator `alt_text` from `data/key-character-images.csv` when non-blank.
- When `alt_text` is blank/null, derive `alt` from the character's `state` name verbatim
  (e.g. state "Black" → `alt="Black"`). Never emit an empty `alt`.
- Rendered via Lit interpolation (auto-escaped); never `unsafeHTML`.

**`<summary>` accessibility copy note:** The visible label "illustration" plus the surrounding
fieldset `<legend>` (the question) and the adjacent state `<label>` give a screen-reader user
enough context. No extra `aria-label` is required; if added, it must read
`aria-label="Show illustration for ${state}"` — but the default visible-text-only approach is
the contract.

## Interaction & Layout Contract (phase-specific)

This section is the load-bearing part of the spec — it resolves the five discretion items
CONTEXT.md left to UI-spec.

### 1. Placement at the per-state row (resolves Discretion #1)

The `<details>` is a **sibling of the state `<label>`, inside the same `<fieldset>`**, emitted
immediately after the label, only when `char.image_filename` is truthy:

```
<fieldset class="pnwm-kfp-question">
  <legend>{question}</legend>
  <label><input type="checkbox"> {state}</label>      ← unchanged
  <details class="pnwm-kfp-help">                       ← NEW, only if image mapped
    <summary>ⓘ illustration</summary>
    <img …>
  </details>
  <label><input type="checkbox"> {next state}</label>  ← next state, no image → no <details>
  …
</fieldset>
```

Contract rules:
- The `<details>` MUST be **outside** the `<label>` element. Nesting it inside the label would
  capture clicks meant for the checkbox and break the existing click target. (RESEARCH Pattern 4.)
- The `<details>` MUST NOT break the OR-within-question grouping: it carries no checkbox, no
  selection, and does not participate in `_selection`. It is purely presentational.
- One `<details>` per mapped state (D-05 per-state mapping). A question with three states where
  only one has an image shows exactly one expander, attached to that state.
- A question/state with no mapping renders no `<details>` (the `${img ? html\`…\` : ''}` guard).

### 2. Summary affordance (resolves Discretion #2)

- `<summary>` content: glyph `ⓘ` (U+24D8) + a thin space + the word `illustration`.
- Styled as a small muted inline affordance — NOT a Pico button, NOT a checkbox-like row.
  Reset Pico's default `summary` marker treatment is acceptable, but **keep keyboard operability**:
  `<details>/<summary>` is natively focusable and toggles on Enter/Space — do not `all: unset`
  away its focusability or add `tabindex` hacks.
- Resting color: `var(--pico-muted-color)`. Hover/focus color: `var(--pico-primary)`.
- `cursor: pointer`. Focus: `outline: 2px solid var(--pico-primary); outline-offset: 2px;`
  (mirrors `.pnwm-krg-card:focus-visible`).
- The default disclosure triangle may be kept or replaced with the site's existing `▶`/rotate
  convention (`.pnwm-kfp-category` uses `▶` rotating to 90° on expand). Either is acceptable;
  if a custom marker is used it MUST mirror the existing `▶` rotate pattern for consistency.
  The `ⓘ` word-label is required regardless of marker choice.

### 3. In-panel image sizing (resolves Discretion #3)

Source images vary widely (399×206 landscape up to 1080×1317 portrait); the panel column is
**280px wide** (`grid-template-columns: 280px 1fr`), with content indented `1.5em`, leaving
~230px usable. The image must never overflow the sticky panel or force horizontal scroll.

| Property | Value | Rationale |
|----------|-------|-----------|
| `max-width` | `100%` (of the indented `<details>` content box, ≈ 224–230px) | Never wider than the panel column |
| `width` | `auto` | Preserve intrinsic aspect for landscape strips |
| `height` | `auto` | Preserve aspect |
| `max-height` | `320px` | Caps tall portraits (e.g. 1080×1317) so one open expander never dominates the sticky panel viewport |
| `object-fit` | `contain` | No cropping of diagnostic detail (this is an ID aid) |
| `display` | `block` | Removes inline-gap; sits in the open image block |
| `loading` | `"lazy"` | Native lazy-load — images only fetched when their `<details>` is opened/visible (consistent with grid `loading="lazy"`, GRID-02) |
| `border-radius` | `2px` | Matches `.pnwm-krg-*` / placeholder radius |
| `decoding` | `"async"` | Optional; non-blocking decode |

- Single image per state (D-05). No gallery, no zoom, no lightbox this phase.
- The `<img src>` is the CDN-absolute URL `${CDN_BASE_URL}/key-images/${encodeURIComponent(file)}`
  where `file` already ends in `.webp`. It is **host-absolute and MUST NOT be wrapped in
  `this._prefix` / pathPrefix** (RESEARCH Pitfall 1; project memory). Warning sign for the
  checker/auditor: any `src` beginning `/pnwmoths/https`.

### 4. No-JS behavior (resolves Discretion #4)

**Help images are JS-panel-only and OUT OF SCOPE for the no-JS static fallback.**
- Rationale: the live panel is client-rendered by `pnwm-identify`; the no-JS fallback (Phase 41
  D-08) is a deliberately lightweight plain-text character + species hierarchy. Injecting up to
  ~77 CDN `<img>` tags into the no-JS page would add weight and network requests against the
  page-weight budget (KEY-04 posture) for a best-effort enhancement.
- Contract: the `<noscript>` / static fallback in `src/identify/index.njk` is **unchanged** by
  this phase. It shows neither expanders nor images. This is the recommended, locked behavior.

### 5. Visual treatment — open/closed states (resolves Discretion #5)

- **Closed (default):** only the muted `ⓘ illustration` summary line is visible, indented under
  the state label. Minimal vertical footprint (`padding: 4px 0`). It must be visually subordinate
  to the state checkbox label above it.
- **Open:** the image block appears below the summary on a light cream tint (`#f0ece0`),
  `border-radius: 2px`, `margin-top: 8px`, with the image sized per §3. No heavy box border;
  an optional `2px` olive-tint left rule (`#d6d0bc`) may tie the open block to its row.
- Transition: none required (native `<details>` toggle). Do not add JS-driven animation.
- All expanders default to **closed** on render (native `<details>` without `open` attribute).

**Proposed CSS (executor reference — mirrors `pnwm-kfp-*` conventions, tokens above):**
```css
/* --- Character illustration help expander (Phase 43) --- */
.pnwm-kfp-help {
  margin: 4px 0 8px 1.5em;
}
.pnwm-kfp-help > summary {
  cursor: pointer;
  font-size: 0.875rem;
  color: var(--pico-muted-color);
  padding: 4px 0;
  list-style: none;          /* if using the ⓘ glyph instead of native marker */
}
.pnwm-kfp-help > summary:hover,
.pnwm-kfp-help > summary:focus-visible {
  color: var(--pico-primary);
}
.pnwm-kfp-help > summary:focus-visible {
  outline: 2px solid var(--pico-primary);
  outline-offset: 2px;
  border-radius: 2px;
}
.pnwm-kfp-help[open] > summary {
  margin-bottom: 4px;
}
.pnwm-kfp-help img {
  display: block;
  max-width: 100%;
  width: auto;
  height: auto;
  max-height: 320px;
  object-fit: contain;
  margin-top: 8px;
  background: #f0ece0;
  border-radius: 2px;
}
```
