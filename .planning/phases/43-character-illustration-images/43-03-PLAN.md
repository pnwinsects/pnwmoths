<objective>
Deliver the build half of CIMG-02 (populate `Character.image_filename` + `alt_text` from the curator CSV) and all of CIMG-03 (the per-state `<details>/<summary>` help expander in the filter panel, plus its CSS). `build-key.ts` currently hardcodes `image_filename: null` at :234-238; this plan reads `data/key-character-images.csv` (soft-skip if absent, warn + skip on out-of-range `char_id` — D-08) and assigns both fields per character. `pnwm-identify.ts` `_renderQuestion()` emits a `<details>` as a SIBLING of the state `<label>` (UI-SPEC §1 — outside the label so it never captures checkbox clicks) only when `char.image_filename` is truthy, sourcing the host-absolute CDN URL (RESEARCH Pitfall 1 — never `this._prefix`).

To keep the load-bearing URL/escaping/pathPrefix-guard logic testable WITHOUT a render-to-string dependency (the project has only `lit` + `node-html-parser`, and RESEARCH locks "zero new dependencies" — no `@lit-labs/ssr`/jsdom), the URL construction and alt-text derivation are extracted into TWO pure, exported helpers — `characterImageSrc(image_filename)` and `helpImageAlt(state, alt_text)` — that `_renderQuestion()` consumes. The existing `pnwm-identify.test.ts` asserts plain method returns (Maps/counts) and never renders a `TemplateResult`; these helpers let the load-bearing assertions run as plain string-return checks in that same idiom. `theme.css` gets the UI-SPEC §5 `.pnwm-kfp-help` rules.

Purpose: Make curator-mapped illustrations visible on demand in the live panel, fully degrading to nothing when unmapped.
Output: Updated build step + tests, updated panel component (pure helpers + render) + helper unit tests, expander CSS, and a UAT confirming the live CDN image appears.
