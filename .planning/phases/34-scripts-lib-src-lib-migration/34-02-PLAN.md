<objective>
Convert all four `scripts/lib/*.js` shared libraries to strict TypeScript, atomically updating every consumer's and every test's import specifier to the `.ts` extension in lockstep. Establish the external-boundary typing pattern (minimal consumed-field interface + hand-rolled guard) and the `COLUMNS`-derived `ManifestRow` + `ManifestStatus` union that Phase 35 will replicate across the rest of `scripts/`.

Purpose: `scripts/lib/` is the producer layer of the build pipeline. Converting it first proves the Node 24 native type-stripping path end-to-end and unblocks Phases 35–38. The #1 risk is cross-extension imports: Node 24 does NOT rewrite specifiers, so a `.js` consumer importing `./lib/manifest.js` throws `ERR_MODULE_NOT_FOUND` the moment `manifest.js` becomes `manifest.ts`. Every rename is therefore paired with its consumers' specifier updates in the same task/commit.

Output: `manifest.ts`, `parse-photo-filename.ts`, `dropbox-list.ts`, `dropbox-download.ts` (+ three converted `.test.ts`), with `ingest-photos.js`, `tile-photos.js`, `upload-tiles.js`, `generate-species-photos.js` updated to `.ts` specifiers.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Dropbox HTTP API → `dropbox-list.ts` / `dropbox-download.ts` | Untrusted JSON/bytes from the Dropbox API cross here. This boundary pre-exists Phase 34; conversion only adds consumed-field interfaces + guards. |
