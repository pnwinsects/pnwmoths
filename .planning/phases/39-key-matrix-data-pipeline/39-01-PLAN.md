<objective>
Build the complete data pipeline that turns the legacy Lucid `key.csv` into the validated,
client-loadable artifact `data/key-matrix.json` plus `data/key-coverage-report.json`. This
plan delivers the *stable data contract* every later v4.0 phase (40–43) depends on: source
CSV committed, character hierarchy parsed, all 1,228 key binomials slug-resolved (with
synonym fallback), nav images joined via DuckDB, per-character-state base64 bitsets emitted
over matched species only, Zod build-time validation, and a `zod/mini` load-time guard.

Purpose: Without this artifact nothing downstream works. It must be correct and reviewable
in git (D-07) before any filter logic (Phase 40) or UI (Phases 41–42) is written.
Output: data/key-characters.csv, data/species-synonyms.csv (16 Grammia rows), schemas in
src/types/schemas.ts, validateKeyMatrix in src/components/key-matrix-cache.ts, the
scripts/build-key.ts pipeline + tests, and the committed data/key-matrix.json +
data/key-coverage-report.json artifacts.
</objective>

| T-39-SC | Tampering | npm/pip/cargo installs | accept | No package installs in this phase — all deps (`csv-parse`, `@duckdb/node-api`, `zod`, Node `zlib`) already in package.json (RESEARCH Package Legitimacy Audit: nothing new) |
