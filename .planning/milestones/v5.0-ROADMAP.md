# Milestone v5.0: Administrative Districts — County Assignment & Browse Filter

**Status:** ✅ SHIPPED 2026-07-06
**Phases:** 44–48
**Total Plans:** 16

## Overview

Give every occurrence record an accurate county / regional-district — re-joining the
curated legacy assignments, deriving from coordinates to fill gaps and catch data-entry
errors — and add a county/regional-district filter to the Browse page scoped to the PNW
region. (Issues #25, #96.)

Delivered as maintainer-run, additive-only scripts that write back into committed
`data/records.csv` (the static-site equivalent of "assign on upload"), plus a
non-blocking QC report and a cascading Browse filter. Merged to `main` via PR #122.

### Phase 46: Coordinate → District Assignment

**Goal**: Every georeferenced record without a stated district gets one derived from its coordinates, using a shared, guarded point-in-polygon module, and the whole assignment workflow is documented as a repeatable maintainer step
**Depends on**: Phase 45
**Requirements**: DIST-04, DIST-05, DIST-06
**Plans**: 3 plans in 3 waves

Plans:

- [x] 46-01: Shared DB-free axis-order/bounds guard module + unit tests (DIST-04)
- [x] 46-02: Coordinate-fill CLI — DuckDB containment + nearest-boundary fallback, additive write, report; tests (DIST-04, DIST-05)
- [x] 46-03: Run fill on real records.csv (≥99% valid-coord fill), commit `coord-fill-report.csv`, author DIST-06 runbook (DIST-05, DIST-06)

**Details:**

**Success Criteria:**
1. The shared PIP module rejects/flags any coordinate pair outside the bounds gate (lat ∈ [41, 61], lon ∈ [−140, −109]) and applies a mandatory lon/lat axis-order check first — verified against `data/records-bad-coords.csv`
2. The coordinate-fill script assigns districts to previously-blank georeferenced records using only coordinates, additively — no non-blank stated value overwritten
3. A coordinate just outside all polygons (coastal/near-water) is assigned via a nearest-boundary-within-tolerance fallback rather than left unassigned
4. After Phase 44 + this phase, district fill rate for records with valid coordinates reaches ≥99%
5. A maintainer-facing `_instructions/` runbook documents the legacy re-join + coordinate fill as a repeatable additive step

**Outcome**: Axis-order guard fires before the bounds gate; fallback ranks candidates via `QUALIFY ROW_NUMBER() OVER (PARTITION BY row_id ORDER BY deg_dist ASC) = 1`. Overall fill 57.90% accepted as documented — root cause is Phase 45's Alberta acquisition scope (only CA:4804 acquired); excluding AB, valid-coord fill is 99.58%.

### Phase 47: QC Mismatch Report

**Goal**: Curators can see, in a non-blocking build artifact, every record whose stated district disagrees with its coordinate-derived district (or whose coordinates fall outside all known boundaries), tiered by severity so the report stays reviewable rather than becoming noise
**Depends on**: Phase 46
**Requirements**: QC-01, QC-02, QC-03
**Plans**: 5 plans

Plans:

- [x] 47-01: RED test scaffolds for the three new scripts + package.json test registration
- [x] 47-02: Full-coverage derivation (`derive-district-audit.ts`) + committed `records-derived-district.csv` + ASSIGNING_DISTRICTS.md
- [x] 47-03: District-adjacency (`build-district-adjacency.ts`) + committed `district-adjacency.csv` + REFRESHING_BOUNDARIES.md
- [x] 47-04: Build-time emit step (`emit-records-district-audit.ts`, pure joins + tiering + D-07 coverage gate) + build:site wiring
- [x] 47-05: Phase gate — full suite + full build + unlinked assertion + curator-legibility human-verify

**Details:**

**Success Criteria:**
1. `npm run build` emits `_site/records-district-audit.csv` on every run, and the build succeeds whether or not mismatches are found — no mismatch ever fails the build
2. Every flagged row is bucketed into one confidence tier (same / adjacent-and-close / far-mismatch / outside-all-boundaries), sorted by severity, with per-tier summary counts
3. A record with missing/null coordinates passes through with no district assigned and is never flagged as a mismatch
4. The audit CSV is not linked from any page — reachable only by direct URL, mirroring `species-audit.csv`

**Outcome**: `build-district-adjacency.ts` wraps ST_DWithin operands in `ST_Boundary()` (this DuckDB spatial build silently returns 0/true for raw Polygon-Polygon pairs). Audits join strictly by `row_index` (positional), never content — `(species_slug, lat, lon, state, county)` is empirically non-unique. Tier-summary counts moved from a `#`-commented CSV preamble into a JSON sidecar (`_site/records-district-audit-summary.json`) to keep the CSV RFC-4180 valid. Zero name-fallback rows against real data — crosswalk now covers every distinct (state,county) pair.

## Milestone Summary

**Key Decisions:**

- Assignment is additive-only and never overwrites a curator-stated county; disagreements are flagged, never silently replaced (issue #25's stated intent)
- `district_id` typed VARCHAR / `z.nullable(z.string())` everywhere — prefixed stable IDs (`US:`/`CA:`), never INTEGER — preserving zero-padded GEOID/CDUID
- Crosswalk uses stable IDs (US GEOID / BC CDUID); joins never depend on raw name string-matching
- QC report is advisory: the build never fails on a mismatch (legacy georeferencing noise near boundaries would block deploys)
- Tier-summary counts live in a JSON sidecar, keeping `records-district-audit.csv` RFC-4180 valid
- Browse filter compound-keyed `${state}:${district}` to avoid cross-state county-name collisions
- Alberta and eastern-MT excluded from the Browse dropdown (out of PNW scope) but records retain any assigned district

**Requirements Delivered:** 14 / 14 (DIST-01…06, QC-01…03, BFILT-01…05)

**Issues Resolved:** #25 (district assignment + QC), #96 (Browse district filter)

**Technical Debt / Open Items Incurred:**

- Alberta boundary coverage is partial (only CA:4804 acquired in Phase 45), capping overall coordinate-fill rate; excluding AB, valid-coord fill is 99.58%. Widening AB coverage is a future acquisition task.
- 2,660 pre-existing BC rows have a county name but no `district_id` (additive-only skipped them); fix is a straight crosswalk name-lookup pass (deferred).
- Two known-stale StatCan district names carried verbatim; a Browse display override is deferred.
- Phase 45's PLAN/SUMMARY execution artifacts were not retained in `.planning/phases/`.

**Deferred to v5.x (tracked in archived REQUIREMENTS):** QCX-01 (distance-to-boundary score), QCX-02 (accepted-exceptions override CSV), BFILT-06 (typeahead combobox), BFILT-07 (multi-select).
